# Veolia VRSI pentru Home Assistant — plan de implementare

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Un add-on HA (`veolia_bridge`, Chromium headless) care citește contul de pe clienti-vrsi.veolia.ro și o integrare custom (`veolia_vrsi`) care transformă datele în entități, statistici lunare/anuale și dashboard.

**Architecture:** Add-on-ul expune pe rețeaua internă Supervisor un server aiohttp (`/health`, `/snapshot`, `/submit-index`) protejat cu token; pentru fiecare cerere pornește Playwright, face login și apelează endpoint-urile JSON ale portalului cu `fetch()` din pagină. Integrarea (structură copiată din `../ha-premierenergy/custom_components/premierenergy`) cere snapshot-ul, îl interpretează în `parser.py` și publică entitățile per loc de consum.

**Tech Stack:** Python 3.13+, Playwright (Chromium), aiohttp, Home Assistant 2026.11 APIs, pytest + pytest-asyncio + pytest-aiohttp, pytest-homeassistant-custom-component.

**Spec:** `docs/superpowers/specs/2026-11-24-veolia-design.md` (citește secțiunile 4 și 5 înainte de orice task).

## Global Constraints

- Domeniu integrare: `veolia_vrsi`; slug add-on: `veolia_bridge`; port intern bridge: `8099`, **fără** port mapat pe host.
- Portal: `https://clienti-vrsi.veolia.ro`; cererile sunt `POST` JSON cu header `Csrf-Token` luat din `#csrf_token`.
- Endpoint-uri permise: `login-submit`, `get-client-codes`, `get-consumption-locations`, `get-contracts`, `get-last-index`, `get-index-history`, `get-last-invoice-and-total-payments`, `get-unpaid-invoices`, `get-invoices`, `get-payments`, `save-index` (doar din acțiunea utilizatorului). **Niciun alt endpoint.**
- Nu se încearcă rezolvarea CAPTCHA / ocolirea WAF altfel decât prin încărcarea normală a paginii în Chromium. Dacă nu apare `#csrf_token` → eroare `waf_blocked`.
- Parola nu se scrie în loguri, în `/data` al add-on-ului sau în diagnostics.
- Arhitecturi add-on: `amd64`, `aarch64`.
- Interval implicit 6 h, minim 2 h, maxim 24 h.
- Texte UI și documentație în română (`strings.json` + `translations/ro.json`), cu `translations/en.json`.
- Unități: bani `RON`, apă `m³` (`UnitOfVolume.CUBIC_METERS`, `SensorDeviceClass.WATER`).
- Date `"0000-00-00"` și șiruri goale = lipsă (`None`).
- Entity ID previzibil: `<platform>.veolia_vrsi_<cod_loc_consum>_<cheie>`.
- Commit local după fiecare task; **fără push** (utilizatorul creează repo-ul GitHub și face push manual).

## Review Focus

1. **Cont cu mai multe coduri client / locuri de consum / loc fără contor** → fiecare loc devine un dispozitiv separat; un loc fără contor are entitățile de index `unknown`, restul funcționează. (Test: Task 1 `test_multiple_accounts_and_meterless_location`.)
2. **Add-on oprit sau în repornire** → `UpdateFailed`, entități indisponibile, **fără** reauth. (Test: Task 6 `test_bridge_down_is_update_failed_not_reauth`.)
3. **Snapshot lent** (login + 10 cereri ≈ 15–40 s) și buton apăsat în timpul unei actualizări → bridge-ul serializează cererile; timeout-ul clientului (180 s) depășește timeout-ul bridge-ului (150 s). (Test: Task 3 `test_requests_are_serialized`.)
4. **Statistici reimportate la fiecare actualizare** → aceleași valori, `sum` cumulat identic, fără dubluri; două perioade în aceeași lună se adună. (Test: Task 8 `test_statistics_idempotent_and_merge_same_month`.)
5. **Cont nou fără facturi/plăți/istoric** → senzorii arată `0`/`unknown`, nimic nu aruncă excepții. (Test: Task 1 `test_empty_account`.)

### Task 3: Bridge — server HTTP

**Files:**
- Create: `veolia_bridge/app/server.py`, `tests/bridge/test_server.py`

**Interfaces:**
- Consumes: `PortalError`, `build_snapshot`, `build_save_index_body` (Task 2).
- Produces:
  - `class Portal(Protocol)`: `async def snapshot(email: str, password: str) -> dict`; `async def submit_index(email: str, password: str, client_code: str, meter: str, index: int) -> dict`
  - `def create_app(portal: Portal, token: str, version: str, op_timeout: float = 150.0) -> web.Application`
  - Rute: `GET /health` → `{"status": "ok", "version": ..., "busy": bool}` (fără token); `POST /snapshot` body `{email, password}`; `POST /submit-index` body `{email, password, clientCode, meter, index}`.
  - Auth: header `Authorization: Bearer <token>` obligatoriu pe `POST`; lipsă/greșit → 401 `{"error": {"code": "unauthorized", ...}}`.
  - Erori: `PortalError` → JSON `{"error": {"code", "message"}}`. Statusul 401 e rezervat token-ului bridge-ului; pentru portal: `auth`→`403`, `not_allowed`/`bad_request`→`400`, `waf_blocked`→`503`, `timeout`→`504`, `portal`→`502`. Corp invalid → `400 bad_request`.
  - O singură operație simultan (`asyncio.Lock`); fiecare operație e limitată la `op_timeout` secunde → `timeout`.
  - Parola nu apare în nicio linie de log (logați doar endpoint, durată, cod eroare).
